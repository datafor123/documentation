Importing the Sample Reports

About 1399 wordsAbout 5 min

SetupUpgrade

2026-11-23

A new 10.02 installation already has the sample reports in Public › Samples. An installation upgraded from an earlier version does not: download the sample package and run its importer once. It brings the reports together with the models and data they need, so they open for everyone straight away.

Download

FileContents
datafor-samples-10.02.zip (1.9 MB)The importer, import.bat and import.sh, import-settings.txt and a README, plus the content below.

SHA-256: 1542675c123da2c519defb800882b8c648ab6e7694958d0bc7e247b9e14646e3

What it adds:

Public › Samples11 dashboards (three of them in the Drill-through Pages subfolder) and 7 paginated reports in Paginated Reports
Analysis modelsLarkwood Retail Sales, Swiftline Global Network, Lifestats, Brightside Online Sales, Halden Group Financials, Kestrel Subscriptions, Halden Group Income Statement, Halden Group Balance Sheet
File datasetsLarkwood Retail Demo, Swiftline Global Demo, Lifestats Sample, Brightside Online Sample, Halden Financials Sample, Kestrel Churn Sample, Halden Income Statement Sample, Halden Balance Sheet Sample

All companies and people in the data are fictional. The package has no foodmart samples and does not change workshop-model.

Before you import

  • Upgrade to 10.02 first and make sure Datafor is running and you can sign in. See Upgrading Datafor. On an earlier version the importer says so and stops before it changes anything.
  • An administrator account. To import into a tenant, use an administrator of that tenant and note the tenant ID.
  • Where to run it. The importer talks to Datafor over HTTP, so the server does not need internet access. Run it on the Datafor server: it finds the Java that comes with Datafor (bi-server/jre). On another computer that can reach the server, it needs Java 8 or later on the PATH, or in DATAFOR_JAVA (the full path of the java program).

Import

  1. Unzip the package, for example on the server.

  2. Start the importer:

    • Windows: double-click import.bat, or run it in a command prompt.

    • Linux: in the unzipped folder, run

      sh import.sh

  3. Answer the questions. Press Enter to keep the value in brackets.

    QuestionEnter
    Server addressThe address you open Datafor with, default http://localhost:28080/datafor
    Administrator accountDefault admin
    Tenant IDEmpty for the default tenant
    PasswordThe administrator's password (not shown while you type)

  4. The importer signs in, checks the server and lists what it will do, then asks Continue? [Y/n]. Press Enter.

    To import:
  File datasets 8
  Models        8
  Reports       18  -> /public/Samples
  Into the default tenant only; other tenants are not affected.
Continue? [Y/n]:

  5. It imports the datasets, then the models, then the reports, and finally checks every item: each model must answer a query and each paginated report must render. The last line reads Done: 44 succeeded, 0 skipped, 0 failed. A log, import-<date>-<time>.log, is left in the package folder.

The messages follow the language of the computer it runs on; add --lang en or --lang zh to choose.

After the import

  • Home. Sample reports now lists reports from Public › Samples, with View all. Which five it shows depends on the order the samples were imported in; to bring a report to the front, open it and save it again. Dashboard covers appear the first time Home shows them, which needs the render service. If Branding still has saved report cards, Home keeps showing those. See Sample reports.
  • Permissions. Public › Samples is read-only for signed-in users and fully editable by administrators. The 8 models and the database connections of the 8 datasets are read-only for the user types SYS_Reader and SYS_Creator and fully editable by administrators, like the built-in foodmart connection, so people who are not administrators can open the samples but cannot change or delete them.
  • Tenants. The samples go into the tenant you signed in to. Other tenants are not changed and keep their Home as it was.

Running it again

Running the importer again is safe: datasets, models and reports that already exist are skipped, and the check at the end runs again. It also sets the permissions of existing sample models and connections back to read-only for SYS_Reader and SYS_Creator.

SituationWhat happens
Something already existsSkipped. Add --overwrite to replace it: datasets are emptied and loaded again, models and reports get the package's content. The importer lists every item it will replace and continues only after you type yes.
Public › Samples already exists with reports of your ownThe importer lists those reports and asks Put the samples into this folder anyway? [y/N]. Your reports are not changed and the folder keeps its permissions, but Home shows the five most recently modified reports of the folder, so it may show samples afterwards.

Options

OptionUse
--url ADDRESSServer address
--user ACCOUNTAdministrator account
--tenant TENANT_IDTenant to import into
--overwriteReplace datasets, models and reports that already exist, including their data
--yesDo not ask for any confirmation
--lang zh or --lang enLanguage of the messages
--helpList the options

The password can also be given in the DATAFOR_PASSWORD environment variable. For example, an unattended run on Linux:

DATAFOR_PASSWORD='…' sh import.sh --url http://localhost:28080/datafor --user admin --yes

Settings file. Instead of typing the address, account and tenant each time, fill them in once in import-settings.txt in the package folder (url, user, tenant, and optionally overwrite, yes and lang). When url is set, the importer asks only for the password. Options on the command line win over the file. Do not put the password in the file.

Tenants and template0

A file dataset's name is unique on the whole server, across tenants. The samples can therefore be imported into one ordinary tenant per server; importing into a second one stops with this dataset name is already used by another tenant on this server, before any report is added.

template0, the template new tenants are created from, is the exception. Import into it with its administrator account:

sh import.sh --user admin-/pentaho/template0 --tenant template0

template0 gets its own copy of the datasets, named with Template at the end (for example Larkwood Retail Demo Template), and its models are pointed at them. It does not matter whether the default tenant already has the samples. Tenants created from template0 afterwards get the samples, models and connections with it, and read template0's copy of the data. Tenants that already exist are not changed.

Troubleshooting

MessageWhat to do
This server runs an older Datafor; the samples need Datafor 10.02 or later.Upgrade first. Nothing was changed.
Cannot reach <address>Check the address and that Datafor is running. From another computer, check that the port is open.
This address is not a Datafor serverThe address answers, but it is not Datafor. Include the /datafor path.
Sign-in failed. Check the account, password and tenant ID.Check all three. A tenant administrator needs the tenant ID.
This account is not an administrator.Use an administrator account.
Java was not found. Enter the Datafor bi-server folderEnter the folder that contains jre, for example /opt/bi-server, or set DATAFOR_JAVA to the full path of java and run again.
[NOTE] … read access for SYS_Reader and SYS_Creator could not be added to its database connection …The dataset was imported, but only administrators can open the samples built on it. Give SYS_Reader and SYS_Creator read access to the database connection named in the message.
[NOTE] … the model's permissions could not be set …The model was imported with the permissions it inherits. Set it yourself: SYS_Reader and SYS_Creator read, Administrator full control, not inherited.
[FAIL] Model query failed or Paginated report does not renderOpen the log in the package folder; it has the server's answer. Run the importer again after fixing the cause: what was imported is skipped.

Removing the samples

  1. Delete the Public › Samples folder in the console.
  2. Delete the 8 analysis models and then the 8 file datasets listed in Download. In template0 the datasets' names end with Template.
